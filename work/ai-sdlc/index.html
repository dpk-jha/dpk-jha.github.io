Case study

Spec to deployment, automated.

An agent-driven delivery pipeline: a spec goes in, and a tested, reviewed, deployed and reported change comes out.

Context
Production product team, employer anonymized
My role
Designed and built the automation, solo
Scope
Spec to deployment, across roughly ten code repositories

What it is

Before the pipeline, AI had sped up one step: writing code. Quality checks, review, deployment and releases were as slow as ever, so the rest of the lifecycle set the pace. The pipeline automates those stages as well as the code, so a spec goes in and a reviewed, tested, deployed and reported change comes out.

I designed and built it on my own, for the product team I work in. It spans roughly ten code repositories.

The stages

Every stage is AI-assisted, with a human involved.

  1. SpecA developer or stakeholder writes the spec, assisted by AI. It describes the change end to end: the requirements, the acceptance criteria and the validation the result must pass. A human owns it.
  2. CodeAgents write the implementation from the spec. Developers also use agents as assistants for work that does not start from a full spec.
  3. Test case generationTest cases are generated for the change, and a human checks that they are the right ones.
  4. E2E automation codeThe test cases become runnable end-to-end automation code, and a human watches how that automation runs.
  5. E2E stack across ten infrastructuresThe automation runs against an end-to-end stack made of ten moving infrastructures, while development and test status is synced in real time to Azure DevOps (VSO), so the board always reflects what the pipeline is actually doing.
  6. PR reviewA separate agent reviews the pull request, not the one that wrote the code.
  7. ReportingResults are compiled into reports.
  8. DeploymentThe change is deployed at the end of the same flow, and a human reviews the outcome after deployment.

Why the e2e stack matters

Generating code and tests is the easy part to demo. Running them against a realistic end-to-end environment is what makes the output trustworthy. Coordinating around ten infrastructures, and keeping Azure DevOps (VSO) in sync with real-time development and test status, is a systems problem, not a prompting problem.

How the output is verified

Agent output is checked against the acceptance criteria, requirements and validation written into the spec, not against the agent's own confidence. The agent that reviews the pull request is a different agent from the one that wrote the code, and the end-to-end run supplies evidence from a real environment.

Where people stay in the loop

AI assists at every stage, and automation does the repeatable work. People keep the judgment calls:

  • The spec. A developer or stakeholder writes it, assisted by AI, so intent and acceptance criteria stay human decisions.
  • The test cases. A human checks that the generated cases are correct.
  • The automation run. A human watches how the end-to-end automation behaves.
  • After deployment. A human reviews the result once the change is live.

What changed for the team

Everything after the first commit got faster, not just the typing:

  • Writing code, generating test cases, automating tests, PR review, deployment and releases all became faster.
  • Updates ship more smoothly, with quality handed off better from the AI.
  • Manual Azure DevOps (VSO) handling is now negligible, because status updates are part of the pipeline.
How I think about it. An agent that can write code but cannot prove it works is a liability. I build the verification, review and reporting around the agent, so its work is checked by something other than the agent's own confidence.

The same ideas, in the open

The open-source tools on this site come from the same problem: running coding agents in a way that keeps them honest, verifiable and easy to supervise.

  • AntiBluff: rules that stop agents from assuming, bluffing or reporting unverified claims.
  • AntiClimax: a strict self-review loop so agents do not declare victory early.
  • GhostPM: a local-first task ledger for AI coding sessions, syncing to GitHub Issues or Azure DevOps.
  • Terminal Studio: one focused window for running several agents in the CLI at once. Each project lives in its own color-coded workspace, so it is clear which agent is working where and the contexts stay apart.
